Description: 
The CSIS IT Ticket and Log System is a web-based application for the NWU Computer Science and Information 
Systems department. It replaces manual email-based IT reporting with structured fault submission, unique ticket 
tracking, technician job cards and start/stop time recording. Students and staff can follow requests and exchange 
comments with technicians. The system provides automated NWU email notifications, escalation records for Central 
IT, immutable audit history and management reporting. This form records acceptance against the functional and 
technical specifications. Results, remedial actions and customer approval are completed after testing.

Criteria 1: 
Functional Requirements determined for the CSIS IT 
Ticket and Log System: 
• NWU email and password authenticate users and 
route each role to its dashboard using a secure 
session; invalid credentials show a clear error. 
Reporter entry follows approved D01. (F01) 
• Names, NWU email and assigned roles persist 
correctly; only authorized administrators can 
change permissions. (F02) 
• The structured submission form captures Title, 
Issue Description, Category, Urgency, Location 
and Station ID using predefined category and 
urgency choices, and confirms successful 
submission. (F03) 
• Clear validation prevents incomplete or invalid 
tickets; corrected input is accepted. Record the 
approved institutional email domains. (F04) 
• Each ticket has a unique Ticket ID, creation time, 
correct reporter association and initial state; all 
fields persist in MongoDB. See D04. (F05) 
• Priority is saved accurately and organizes the 
queue so higher urgency work is visible first; 
hazardous priority is tested separately in T cases. 
(F06) 
• Each reporter sees their own requests and status 
history; another reporter ticket is inaccessible 
through both UI and API. (F07) 
• Authorized technicians see the permitted ticket 
queue, filter by status, inspect history and sort by 
priority. Cards show Station ID, Priority and time 
since submission. Labels follow D04. (F08) 
• The ticket records the technician and claim time, 
moves to the approved active state and updates 
the dashboard and history. (F09) 
• Only approved transitions succeed; the ticket, 
queue and audit history remain consistent for 
New/Pending, Assigned, In Progress, Escalated 
and Resolved as agreed. (F10) 
• Start and stop timestamps persist, active work 
changes the state to In Progress, duration is 
calculated to the second and the displayed total 
matches MongoDB. (F11) 
• The total adds both sessions correctly in 
minutes/hours, persists after reload and has 
timestamped audit entries for the time records. 
(F12) 
Criteria 2: 
Technical and Non-Functional Requirements determined 
for the CSIS IT Ticket and Log System: 
• MongoDB, Express and Node.js implement persistence 
and backend logic. React SPA in FS versus Vanilla 
JavaScript in TS is resolved and evidenced under 
D02. (T01) 
• Node.js is v20.x or greater; Express.js v4.x baseline is 
verified; target is Ubuntu Server 22.04 LTS or 
configured Windows Server with a Node process 
manager such as PM2. (T02) 
• The approved CSIS physical/virtual host supports the 
runtime and persistent ticket/audit storage; data 
location follows the agreed university boundary and 
D05. (T03) 
• Functional parity is recorded for Chrome/Firefox/Edge, 
with FS Safari coverage; Windows 10/11, macOS 
and Linux browser access works without client 
installation. (T04) 
• Mobile workflows match desktop functionality with 
readable responsive layouts and touch-friendly 
controls; FS Android 8.0+ and iOS 11.3+ support is 
documented or dispositioned. (T05)

• Purple/white branding and typography are consistent;

protecting credentials and ticket data in transit; 
unencrypted access cannot expose protected data. 
(T11)

gateway to @nwu.ac.za or @student.g.nwu.ac.za

 Email processing does not block application 
requests and sustained test traffic leaves no 
unresolved notification backlog. (T13) 
• Signed JWTs establish identity and role for protected 
requests; invalid or absent tokens cannot claim, close 
or alter tickets or audit data. D01 governs reporter 
entry. (T14) 
• Management authentication operates using the internal 
module; no unavailable central Active Directory/SSO

integrations remain separately scoped. (T15)
